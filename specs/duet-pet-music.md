# Duet pet × QQ 音乐接入调研

状态：**提案 / 可行性已验证，未开始实现**

目标：让精灵能查看和控制用户正在播放的 QQ 音乐，同时保留会员、音质、版权和 DRM 的官方行为。

## 结论

推荐走 **Windows 系统媒体会话（SMTC）**：

- 控制的是**官方 QQ 音乐桌面客户端**，不是 QQ 音乐私有 API。
- 不读取 Cookie、不登录 QQ 音乐账号、不解析播放地址、不碰 DRM。
- 会员音质、VIP 歌曲、版权限制全部由 QQ 音乐客户端自己处理。
- 精灵只发送“播放/暂停/上一首/下一首”等系统媒体命令。

这条路能做到“控制当前播放”和“看正在播放什么”，但**不能搜索并播放指定歌曲**。后者需要另一条路径（官方 Web 播放器或未公开协议），风险和成本都更高。

## 官方开发者平台 / QPlay Auth 评估

QQ 音乐确实有官方开发者平台：

- 首页：`https://open.y.qq.com/`（跳到 `https://y.qq.com/music_developer/`）
- 文档中心：`https://y.qq.com/music_developer/#/docs/openid#/overview`
- 商务邮箱：`qmopen@tencent.com`

平台提供的能力包括：

- **QPlay Auth（登录鉴权）**：把 QQ 音乐的登录态授权给合作方 App；授权后合作方可以访问 QQ 音乐内容，用户可以在合作产品里使用自己的**个人权益和资产**（也就是会员权益）。
- **OpenAPI / SDK**：合作方按文档调用音乐服务。
- 大屏、车机、智能硬件、公播等解决方案。

关键限制在准入。官方文档写明：合作方需要先在 QQ 音乐开放平台注册业务信息，包括**公司主体、应用名称、应用图标**等信息，审核通过后才能拿到 `appid` / `appkey`。

也就是说，这是**面向公司/合作方**的开放平台，不是个人开发者自助申请 API Key 的平台。文档里的“个人权益”指的是**授权用户自己的会员权益可以在合作方 App 内使用**，不等于“个人开发者可以随便调用播放接口”。

如果用户有公司主体并能通过审核，QPlay Auth 是比 SMTC 更深的官方路径：

- 可以通过 QQ 音乐 / QQ / 微信扫码或拉起 App 完成授权；
- 拿到令牌后按 OpenAPI 访问内容，理论上可以做搜索、指定播放、使用会员权益；
- 但需要应用审核、`appid` / `appkey`、可能的 RSA 密钥、OAuth 令牌刷新、配额和合规审查；
- “桌面宠物/个人助手”是否能作为审核通过的应用类型，需要先问平台。

结论：**个人自用精灵不应该依赖开放平台**。如果没有公司主体和审核通过的 App，QPlay Auth 这条路走不通；即使有，成本和合规要求也远高于 SMTC。

## 本机验证结果

当前 Windows 环境已用 PowerShell 直接读取 SMTC：

```text
sessions=1
app=QQMusic.exe
title=挖空爱你的心
artist=王忻辰/苏星婕
album=王忻辰音乐精选合辑
status=Playing
```

说明 QQ 音乐桌面版会把播放状态发布到 Windows 媒体会话，精灵可以读取。

SMTC 会话对象提供的方法（Windows Runtime 原生）：

| 能力          | 方法                                                           | 说明                                   |
| ------------- | -------------------------------------------------------------- | -------------------------------------- |
| 播放          | `TryPlayAsync`                                                 |                                        |
| 暂停          | `TryPauseAsync`                                                |                                        |
| 播放/暂停切换 | `TryTogglePlayPauseAsync`                                      |                                        |
| 停止          | `TryStopAsync`                                                 |                                        |
| 上一首        | `TrySkipPreviousAsync`                                         |                                        |
| 下一首        | `TrySkipNextAsync`                                             |                                        |
| 快进/快退     | `TryFastForwardAsync` / `TryRewindAsync`                       | QQ 音乐是否实现需实测                  |
| 跳转进度      | `TryChangePlaybackPositionAsync`                               | QQ 音乐是否实现需实测                  |
| 播放速率      | `TryChangePlaybackRateAsync`                                   | 一般不用于音乐                         |
| 随机/循环     | `TryChangeShuffleActiveAsync` / `TryChangeAutoRepeatModeAsync` | QQ 音乐是否实现需实测                  |
| 读取当前媒体  | `TryGetMediaPropertiesAsync`                                   | 标题、艺人、专辑、封面缩略图           |
| 读取进度      | `GetTimelineProperties`                                        | 位置、总时长、可 seek 范围             |
| 读取播放状态  | `GetPlaybackInfo`                                              | Playing/Paused/Stopped、控制按钮可用性 |

## 推荐的产品形态

沿用现在的多窗口原则：**主窗口只做对话，音乐是独立工具窗口**。

```text
精灵主窗口（chat）
   │ 托盘菜单 “QQ 音乐”
   ▼
QQ 音乐工具窗口（独立、可缩放）
   ├─ 当前歌曲卡片：标题 / 艺人 / 专辑 / 播放状态
   ├─ 控制：上一首 / 播放暂停 / 下一首
   ├─ 打开 QQ 音乐
   └─ 出错或未检测到时的空状态
```

不在主聊天窗口里塞播放器；以后可以再加一个很小的 now-playing chip，但不是 v1。

## 数据流

```text
QQMusic.exe
   ↑ 系统媒体命令（play/pause/next/prev）
   │
PowerShell SMTC helper（固定脚本、命令白名单）
   ↑ JSON 状态 / 指令
   │
Electron main（windows/music controller）
   ↑ state 事件 / command IPC
   │
QQ 音乐工具窗口（只读展示 + 按钮）
```

- 精灵主进程是唯一与 PowerShell 交互的一方；renderer 拿不到 shell。
- 只允许固定动作：`state`、`toggle`、`play`、`pause`、`next`、`previous`。
- 窗口打开时每 2.5–3 秒轮询一次；窗口关闭立即停止，不在后台常驻 PowerShell。
- 控制命令是一次性 PowerShell 调用；命令后重新读取状态，UI 以真实状态为准。
- 会话选择优先 `QQMusic.exe`；没有 QQ 音乐会话时显示空状态，不误控浏览器或其他播放器。

## 延迟与资源

- 一次 PowerShell + WinRT 查询约 300–800ms（受机器和首次加载影响）。
- 2.5–3 秒轮询下，QQ 音乐内切歌/暂停在窗口里最多延迟约一个轮询周期。
- 窗口关闭后没有轮询，不占 CPU。
- 如果以后要求更低延迟，可以改成常驻 PowerShell helper + stdin/named pipe；第一版不需要。

## 会员、版权与安全

- 精灵**不接触** QQ 音乐账号、Cookie、播放 URL、音频流或解密密钥。
- 播放发生在官方客户端里，会员音质和 VIP 权益由客户端判断。
- 精灵无法绕过付费/版权限制；VIP 歌曲在 QQ 音乐里不能播时，精灵也控制不了。
- 不引入 QQ 音乐私有 API、签名算法或第三方破解库。
- PowerShell 只执行固定脚本，动作白名单，不接受任意命令或路径。
- 不上传歌曲元数据；所有数据留在本机。

## 失败模式

| 现象                     | 处理                                           |
| ------------------------ | ---------------------------------------------- |
| QQ 音乐没启动 / 没在播放 | 显示“没有检测到 QQ 音乐”，提供“打开 QQ 音乐”   |
| QQ 音乐未登录            | 仍可显示客户端状态；登录由用户在 QQ 音乐里完成 |
| SMTC 没有 QQMusic 会话   | 显示空状态，不控制其他播放器                   |
| PowerShell 被策略阻止    | 显示错误和提示，不影响精灵主功能               |
| 多个媒体会话             | 只选 `QQMusic.exe`，忽略浏览器等               |
| 非 Windows               | 显示“当前平台暂不支持”，或隐藏托盘入口         |

## 不建议的路径

1. **QQ 音乐私有 Web API**：需要 Cookie、签名、播放地址解析，可能涉及 DRM/ToS，版本一变就坏；不做。
2. **自己解密/下载音频**：违反会员/版权边界；不做。
3. **UI 自动化点 QQ 音乐窗口**：脆弱、抢焦点、受窗口布局影响；不做。
4. **QQ 音乐未公开 URL Scheme 做搜索/播放**：可作为后续实验，但不作为 v1 依赖。

## 分阶段

### P0：可行性（已完成）

- 验证 QQ 音乐发布会话到 SMTC。
- 验证可读取标题、艺人、专辑、状态。
- 确认控制方法存在。

### P1：v1 工具窗口

- 托盘新增“QQ 音乐”。
- 独立窗口显示当前歌曲、状态、上一首/播放暂停/下一首、打开 QQ 音乐。
- 只读状态轮询 + 控制命令。
- Windows only；其他平台显示不支持。

### P2：增强

- 进度条 / seek（先实测 QQ 音乐是否支持）。
- 专辑封面。
- 随机/循环。
- 切歌通知 / 托盘 now-playing。

### P3：搜索与指定播放（可选，独立设计）

- 官方 Web 播放器嵌入窗口：登录官方网页，控制播放器 DOM。
- 或未公开的 QQ 音乐协议/深链。
- 需要单独评估稳定性、登录态、版权和 UI 维护成本。

## v1 验收标准

1. QQ 音乐正在播放时，从托盘打开“QQ 音乐”，窗口在 1–3 秒内显示歌名、艺人、专辑和播放状态。
2. 在窗口中点暂停/播放、上一首、下一首，QQ 音乐客户端实际执行，窗口状态在下一个轮询周期内同步。
3. 在 QQ 音乐客户端里操作，窗口状态也会同步。
4. QQ 音乐未启动时，窗口显示空状态，“打开 QQ 音乐”能拉起客户端。
5. 精灵主窗口的对话、上下文、控制台、阅读窗口不受影响。
6. 非 Windows 平台不会误启动 PowerShell，显示 unsupported。
